維運團隊您好：

我是[姓名／團隊名稱]，正在製作「午餐好了沒？」這項免費、非營利的網頁服務。服務讓家長自行輸入學校代碼並訂閱瀏覽器推播；當「校園食材登錄平臺」已刊登當日午餐菜色照片時，系統通知家長前往查看。服務不蒐集家長姓名、電子郵件或兒童資料，也不長期保存來源圖片。

預計的查詢方式與頻率如下：

- 僅查詢有使用者訂閱、且當天尚未成功通知的學校。
- 每日台灣時間 08:00–14:00，每小時至多查詢一次該校當日午餐（`MenuType=1`）；確認照片已刊登後，當天不再查詢該校。
- 先查詢 `/offered/meal` 取得批次代碼，再查詢 `/dish` 判斷照片是否存在；使用者查看照片時，後端才代理請求 `/dish/pic/{DishId}`，並快取 30 天以降低重複流量。
- 初期僅供少量測試使用；若使用規模增加，會先再次與貴團隊確認，不會自行提高頻率。

由於這些介面看來並非正式公告的開放 API，我們希望在公開服務前取得貴團隊同意，並請教：上述用途、端點與查詢頻率是否可以接受？是否有建議的呼叫時段、速率限制、識別標頭或應改用的正式介面？若不適合公開服務使用，我們會停止公開計畫，僅保留個人使用。
