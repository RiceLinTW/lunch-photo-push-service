我是[姓名／團隊名稱]，正在製作「午餐好了沒？」這項免費、非營利的網頁服務。服務讓家長自行輸入學校代碼並訂閱瀏覽器推播；當「校園食材登錄平臺」已刊登當日午餐菜色照片時，系統通知家長前往查看。服務不蒐集家長姓名、電子郵件或兒童資料，也不長期保存來源圖片。

## 查詢方式與頻率

- 僅查詢有使用者訂閱、且當天尚未成功通知的學校。
- 每日台灣時間 08:00–14:00，每小時至多查詢一次該校當日午餐（`MenuType=1`）；確認照片已刊登後，當天不再查詢該校。
- 先查詢 `/offered/meal` 取得批次代碼，再查詢 `/dish` 判斷照片是否存在；使用者查看照片時，後端才代理請求 `/dish/pic/{DishId}`，並快取 30 天以降低重複流量。
- 初期僅供少量測試使用；若使用規模增加，會先再次與貴團隊確認，不會自行提高頻率。

由於這些介面看來並非正式公告的開放 API，我們希望在公開服務前取得貴團隊同意：上述用途、端點與查詢頻率是否可以接受？是否有建議的呼叫時段、速率限制、識別標頭或應改用的正式介面？若不適合公開服務使用，我們會停止公開計畫，僅保留個人使用。

## 學校查詢功能：已測試過官方管道，仍缺一塊資料

為了讓家長能用學校名稱搜尋（而不是要求他們自己先查到代碼），我們已經先嘗試過貴平台所有看得到的正式管道，確認以下事實，想請教是否有我們遺漏的正式方式：

- 已透過 `/cateringservice/openapi/accountReg/` 註冊 OpenAPI 帳號（信箱：`28_pallor_hurrahs@icloud.com`），並成功用存取碼呼叫 `/county/`、`/opendatadataset/`、`/opendatadownload/`。
- 下載了「全國國中小午餐菜色資料集」等批次開放資料集，確認欄位僅有縣市／區域／學校名稱／供餐日期／菜色名稱，**不含任何學校代碼**，無法用來對照。
- 查詢頁（`frontend/search.html`）背後的 `/school?CountyId=&AreaId=&SchoolType=` 端點需要 `X-School-List-Key` 才能列出地區內學校，我們的 OpenAPI 存取碼無法用在這個端點上。
- `/county`、`/area`、`/school/{SchoolId}`（查詢單一已知代碼）這三個端點本身是公開、不需要金鑰的。
- 教育部統計處公開的「國民小學名錄」等開放資料能提供標準學校代碼（例如 `024701`），但這個代碼**不一定**等於貴平台查詢用的 `SchoolId`——我們實測約 2600 筆抽樣中，新北市／臺北市兩者幾乎完全一致（近 98%），但宜蘭、桃園、臺南、高雄、屏東等地幾乎完全不同，無法通用替代。

想請教是否能協助以下任一項：

1. 為我們的帳號另外開通 `X-School-List-Key`（或等效授權），讓我們比照貴平台自己前端的用法，一次查詢一個地區的學校清單（不是批次下載全部學校）；或
2. 提供一份標準學校代碼與貴平台 `SchoolId` 的對照表，讓我們能在自己的服務內建立學校名稱搜尋功能。

若兩者都不方便提供，我們會退回目前「使用者自行到官方查詢頁查代碼、手動輸入」的做法，不會另外嘗試取得學校清單。
